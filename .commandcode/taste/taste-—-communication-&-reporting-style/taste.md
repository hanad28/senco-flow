# Taste — communication & reporting style
- Prefers audit/review findings to be verified against both the live deployment and the repository before being reported, with file:line evidence rather than speculation or unverified claims. Confidence: 0.9
- Wants severity levels calibrated honestly — overstating an issue (e.g., calling something "critical" when it is "major") is treated as a correction, not tolerated. Confidence: 0.85
- Likes structured status reports organized as blocking findings / verified-fixed / production status / checks run, with severity labels on each item. Confidence: 0.8
- When choosing between copy or design alternatives, prefers to be shown a numbered list of options and to approve one ("use 1", "number 2") before anything is implemented; explicitly says "list options, don't change yet". Confidence: 0.85
- Makes visual/layout adjustments through small iterative numeric tweaks (e.g., "move the block down 20%", "10% up") and expects each iteration to be re-checked. Confidence: 0.6
- Expects work to be committed/pushed and to be deployed — asks "Have you deployed?" and "commit and push everything". Confidence: 0.65
